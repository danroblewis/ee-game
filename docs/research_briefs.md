### sim-algorithms
Falstad-style engine in Rust is well-trodden and feasible. Core loop: Modified Nodal Analysis — unknowns = node voltages + currents of voltage-source-like elements; components "stamp" conductances into matrix A and currents into RHS b; C/L become companion models (trapezoidal: cap G=2C/h, Ieq=(2C/h)v_n+i_n; inductor G=h/2L; backward Euler: G=C/h resp. h/L); nonlinear devices (diode exp model, MOSFET) linearized per Newton-Raphson iteration with voltage limiting (pnjlim-style) to prevent exp overflow.

Falstad specifics (confirmed from circuitjs1 INTERNALS.md): wires are merged into single nodes via wire-closure, not stamped; matrix rows with single nonzeros are eliminated (simplifyMatrix); linear circuits LU-factorize ONCE and reuse the factorization every timestep (only RHS changes); nonlinear circuits re-stamp+refactor per NR subiteration with an iteration cap; fixed small timestep (~5 µs default) with as many substeps per 60 Hz frame as a real-time compute budget allows (heavy circuits slow sim-time, never the UI); edits trigger full cheap re-analysis. Digital gates are stamped analog elements (voltage-source output set from input thresholds during NR subiterations); chips use an execute() hook outside the matrix; no event queue. CircuitJS1 is GPLv2 — copy algorithms only.

Numerics: floating nodes/VS loops → singular matrix; fix via topology pre-checks + gmin (1e-12 S node-to-ground) + partial pivoting. Trapezoidal rings after discontinuities → take BE steps after switching events or use TR-BDF2/Gear-2. Convergence rescue: NR damping, halve dt on failure (grow slowly after, cf. circuitjs auto-adjust-timestep), gmin/source stepping only needed if you ever do a DC operating point (Falstad doesn't — startup transient serves as OP; recommended for the game).

Performance: dense LU fine to ~200 unknowns; beyond that use sparse (circuit matrices ~3–5 nnz/row). KLU (SuiteSparse) is the reference circuit solver — its symbolic-once + fast numeric refactor without repivoting is exactly what NR loops need. Rust: faer (pure Rust dense+sparse LU, SIMD, compiles to wasm32 — best default), nalgebra (dense), sprs, klu-rs bindings (C, awkward for WASM), Melange/OpenVAF as prior art. Budget check: ~50k steps/s × few NR iters at n≈100–500 is comfortably one core; a 16-player room of a few thousand unknowns should be solved as independent per-island block matrices (disconnected subcircuits), parallelized per island, coupled only by transmission lines. WASM runs ~1.3–2× slower than native; SIMD128 available in all browsers; client only needs prediction.

Determinism: WASM scalar f64 ops are bit-exact IEEE-754 (only NaN payloads vary); native matches IF you forbid FMA/mul_add, fast-math, and reduction-reordering, and replace platform libm exp/ln with the pure-Rust `libm` crate on all targets. Avoid relaxed-SIMD. Bit-identical native/WASM is achievable; still architect periodic server-snapshot resync.

Mixed-signal: use Falstad's unified stamped-gate approach for glue logic (preserves analog-attack gameplay), plus an event-driven layer (XSPICE-style, but with events quantized to the analog dt to avoid backtracking) for MCUs/large digital blocks, bridged by slew-limited D/A sources and Schmitt-trigger A/D comparators.

### falstad-ux
Falstad's "alive" feel comes from: continuous free-running simulation (never a "run" button), yellow moving current dots whose speed/density encode magnitude and direction, voltage color-coding on wires (green=+, red=−, gray=0V, brightness ∝ magnitude), hover tooltips with live values, single-gesture wire drawing (drag on empty grid = wire; drag on component = move), right-click context menu for edit dialogs, bottom-docked auto-stacking scopes fed by "add to scope" on any component, and interactive components (switches, pots with slider handles) manipulable during simulation. Weaknesses to fix: no undo depth/robustness historically, no component search, clunky menu-based component placement, primitive subcircuits (File→Create Subcircuit with labeled nodes; buggy, no live inspection inside instances), no infinite canvas, no touch UX, no multi-select ergonomics.

Adopt from others: EveryCircuit — tap-empty-space radial/dial component picker, drag-on-value knob editing (drag up/down on any parameter to sweep it live), waveforms drawn beside components in-canvas, finger-drawn input signals, automatic wire routing. iCircuit — always-running sim, touch scope with pinch timebase, multimeter mode (tap any node/element for value). CircuitLab — searchable component browser with typing filter, professional undo/redo, smart wire routing with junction dots, expression-based parameters. Wokwi — "+" button → type-to-search filterable parts list, 0.1in grid snap (Shift disables, Ctrl fine-snap), wires with waypoints, everything serialized to human-readable diagram.json (great precedent for netcode/state). Crumb — proof that circuit-sim-as-game works (Steam "Very Positive" recent, 78% overall); voltage color mapping + real-world 3D view parallels our schematic/physical duality. KiCad/Altium — hierarchical sheets: sheet-as-symbol on parent with hierarchical pins; KiCad's explicit hierarchical labels vs Altium's project-wide net namespace; complex hierarchy = one sheet instantiated N times (reusable IC pattern). Best-in-class subcircuit UX target: double-click to enter a black box in place (Figma component / Fusion-style edit-in-context), breadcrumb trail, live internals still simulating.

Infinite canvas: two coordinate systems (screen/canvas), zoom-to-cursor, standard bindings (wheel=zoom or scroll, space+drag/middle-drag=pan, cmd+0/1/2 fit/100%/selection), semantic zoom = render different representations by zoom level, not just scaling — far: block/IC view with aggregate state (perfect hook: zoomed out = "real world" device view, mid = block diagram, close = full schematic with dots). LOD: cull sub-pixel detail, fade text/labels below thresholds, simplify dot animation when zoomed out.

Beginner pain points and mitigations: unconnected-looking-connected wires (fix: strong snap, explicit junction dots, live connectivity highlight, DRC hints); no ground / floating nodes (fix: auto-detect and suggest, or gameplay-tolerant solver); dead circuit with no feedback (Falstad's fix: continuous animation makes brokenness visible — dots stop); parameter dialogs with SI units (fix: EveryCircuit knob-drag + unit-aware steppers); component overload (fix: curated progressive palette, search, recents); short circuits crash sims (Falstad flashes the offending wire and names the problem — adopt and gamify as component damage). Overall pattern: direct manipulation + always-on simulation + immediate visual feedback is the core loop; every state change should be visible within one frame.

### netcode
Networking research for EE Game (2-16 player rooms, server-authoritative circuit sim + shared schematic).

Key recommendations:
1. THREE-TIER STATE MODEL: (a) schematic document — reliable, server-serialized ops; (b) sim display state — 15-30 Hz snapshots, Quake-3-style delta compression vs last-acked snapshot, viewport-based interest management (client reports viewport rect+zoom, server sends per-component electrical state only for visible components via R-tree culling, aggregates elsewhere); (c) waveform probe streams — lossy, latest-wins, server-side decimated.
2. SCHEMATIC SYNC: Use Figma's model — server-ordered ops with per-property last-writer-wins, fractional indexing, optimistic client apply + server reconciliation. NOT CRDTs: Figma explicitly rejected them (central server makes them unnecessary), tldraw sync likewise is server-authoritative with client rebase ("general-purpose CRDTs aren't built for canvas data"). Extra reason here: every op must be validated against electrical rules and transactionally applied to the netlist/MNA matrices anyway — the server is unavoidably the arbiter.
3. WAVEFORMS: server-side min-max decimation (peak-preserving) keyed to client timebase/pixel width; LTTB only for trend views; binary frames (header + Float32Array or 16-bit quantized w/ scale+offset). Lossy per-probe latest-wins queues; drop/coalesce on backpressure (monitor bufferedAmount / per-conn send queue), never buffer waveforms behind reliable ops.
4. TRANSPORT: Ship on WebSocket (universal, adequate at 10-30 Hz rates). WebTransport became Baseline with Safari 26.4 (Chrome 97+, Firefox 114+, Edge 98+) — plan an abstraction layer with message classes (reliable-ordered / lossy-latest / lossy-stream) so WebTransport (Rust: quinn/wtransport) can slot in later with datagrams for waveforms. Skip WebRTC datachannels (server-side ICE/DTLS/SCTP complexity, webrtc-rs heavy).
5. PREDICTION: Do NOT attempt bit-exact lockstep/rollback between native server and WASM client — FP determinism across targets is achievable (Rapier proves it: IEEE 754 targets, shared libm, no fast-math) but fragile, and analog sims phase-drift chaotically anyway. Instead run the WASM sim as a local preview: optimistic local application of edits + continuous local sim, hard-resynced from each server snapshot (reseed capacitor/inductor/switch/digital states); analog divergence between snapshots is visually invisible, discrete states snap to server truth. Same WASM core powers offline sandbox mode.
6. SERVER: axum + tokio + tokio-tungstenite; plain tokio tasks + mpsc channels per room (2025 consensus: skip actix actor framework). Sim loop on a dedicated thread per room (CPU-bound; never on the async runtime), commands in / snapshots out via bounded channels with lossy policy on state channels. One process hosts many rooms; room-code matchmaking; persistence = schematic op-log + periodic checkpoints (Figma pattern), sim state rebuilt from netlist. Agones/K8s or Durable-Objects-style orchestration is a later scaling path, not needed at launch.

Bandwidth sanity: 500 visible components × ~2 f32 × 20 Hz ≈ 80 kB/s pre-delta (delta+quantization cuts this heavily); 4 waveform probes at ~2-3k pts/s × 2 bytes ≈ 20-25 kB/s. Well within WebSocket comfort.

### scopes-analysis
Instrumentation research findings for EE Game:

UX: Copy Falstad's "probe = click, scope = dock" model, not real-scope knobs. Falstad: right-click "View in Scope", scopes auto-scale in a bottom dock, show V+I per element, no trigger UI (free-running). EveryCircuit: mini-waveforms drawn directly on wires, XY mode, auto grid ticks — its "always-visible waveform on the schematic" is the key intuition win. Recommended: one-click probing (click wire=voltage, click component=current clamp), pinned color-coded probe markers matching trace colors, hover live-value tooltips, drag-to-combine traces, math channels (A−B, V×I power). Never-fight-the-scope = software auto-trigger (edge at (min+max)/2 with hysteresis), period detection (zero-cross + autocorrelation) to auto-set timebase to 2–4 periods, envelope-tracked auto-scale snapped to 1-2-5 steps with hysteresis. Cross-player comparison is trivial because one authoritative sim clock: probes are room-scoped shared entities, overlay any two players' traces on shared sim ticks.

Rendering: 60fps multi-trace needs WebGL/WebGPU. Libraries: webgl-plot (oscilloscope-oriented, minimal) and TimeChart (1M+ pts, GPU pan/zoom); uPlot as Canvas2D fallback. Recommendation: custom WebGL2 renderer (WebGPU when available) using instanced-quad line segments + fragment-shader SDF antialiasing (native GL line width is capped ~1px on ANGLE). GPU-resident ring buffer VBO updated via bufferSubData; OffscreenCanvas in a worker. Downsampling: min-max per-pixel-column decimation for waveforms (preserves glitches/envelope — better than LTTB for signals); LTTB only for smooth history browsing; multi-resolution min/max pyramid (factor 4) gives O(log n) zoomable history like audio editors.

Analysis: FFT via rustfft in shared WASM/native core; defaults: Hann window (industry general-purpose default), 4096 pts, dB magnitude, Welch averaging option, flat-top for amplitude accuracy, parabolic peak interpolation. Auto-measurements: Vpp/Vrms (over integer periods)/mean/freq/duty/rise-fall/phase-between-traces, shown as live chips. XY mode incl. I–V curve tracer + phosphor persistence. Logic view: auto threshold, bus grouping to hex. Protocol decoding modeled on sigrok: streamed chunked decoding, stackable decoders (bits→frames→messages), time-spanned annotation rows; make decoders unlockable gameplay (tap enemy lines, decode, then inject/jam).

Data model: sim fixed timestep (10–50 µs sim-time); probe sampling decimated from sim ticks; timestamps = sim tick indices, never wall clock; resample to uniform rate before FFT if timestep adapts. Client: ~10 s full-rate f32 ring per active probe (50 kHz ≈ 2 MB) + pyramid (~1.3× overhead). Server: few seconds full-rate per subscribed probe + long-horizon pyramid summaries only. Subscription protocol: client subscribes (node/branch, rate), server sends 16–33 ms batched frames; when zoomed out send min/max pairs per column; 16-bit fixed-point quantization halves bandwidth (raw f32 50 kHz = 200 kB/s/probe). Own-circuit WASM sim gives zero-latency local preview, reconciled by tick index. SharedArrayBuffer rings between network/analysis/render workers.

### prior-art
Prior-art research for EE Game (schematic-drawing multiplayer with real circuit sim). Key findings:

1) Zachtronics (TIS-100, Shenzhen I/O, Opus Magnum): fun comes from open-ended puzzles with fixed I/O specs, post-solve histograms (cost/size/power vs other players) that drive endless optimization, and fiction (fake inbox/manual) giving context. TIS-100 outsold friendlier Infinifactory 2:1 — depth for a niche beats watered-down breadth. Turing Complete's "gates→CPU" abstraction ladder is beloved. Virtual Circuit Board (91% positive) thrives as pure sandbox with great editor ergonomics. Logic World: built-for-multiplayer collaborative logic building, huge fast simulation is a selling point.

2) Casual engagement (Factorio circuits, ONI smart battery, Minecraft redstone): electricity engages casuals when OPTIONAL, when the simplest useful device is trivial (ONI: battery+wire+generator = automated power), when feedback is visible/animated, and when learning is copy-paste-then-tinker (redstone tutorials, Factorio cookbook). Forcing circuit mastery makes casuals quit.

3) Screeps is the cautionary tale for automation PvP: 24/7 offline automation means vets wipe newbies; erasing a player is EASIER than partial theft; open-source bots dominate; almost no "fair, interesting fights." Do: session/room scale (already locked) fixes most of this; make attacks degrade (brownouts, jamming) not annihilate; cap loss.

4) Shared contraptions: Wiremod = long-lived proof players love shared-server wired contraptions; Stormworks warns that physics-heavy multiplayer sync is misery (EE Game's deterministic MNA sim avoids this) and that gating basic logic behind progression while leaving powerful microcontrollers open backfires. 

5) POWER/DATA warfare precedent is thin = differentiator. Closest: Space Station 13/Barotrauma (sabotage of wiring/solar/APCs generates legendary emergent stories; asymmetric saboteur roles), Mindustry PvP (power lines are prime targets), real-world Industroyer/Ukraine grid attack (protocol-level breaker attacks — rich design source). No game does analog signal warfare (jamming, spoofing waveforms, impedance attacks) — genuinely novel territory.

6) Core loop: pure sandbox stalls without goals; best pattern = scenario/spec-driven challenges (produce this waveform, power this load through faults) + histogram/leaderboard optimization + blueprint/schematic sharing + sandbox for mastery expression. Session loop: build→instrument→debug→optimize→defend/attack. Scopes/probes ARE the fun (Zachtronics debuggers prove watching your machine run is the reward).

Top do's: visible animated current flow; trivially small first circuit; optional depth; blueprint sharing; degrade-not-destroy PvP; asymmetric attack/defense costs favoring defender; spec-based challenges with multi-metric scoring. Top don'ts: mandatory logic literacy; permadeath of contraptions; unbounded offline automation advantage; physics sync; locking primitives behind progression.
